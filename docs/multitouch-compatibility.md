# 五指手势兼容性记录

## 1.12.1：系统升级后无法全局打开

诊断环境：macOS 26.6.2（25G83）、Apple Silicon arm64、系统自带
MultitouchSupport 9460.1。原 1.12.0 仅允许 9450.2，导致新系统在创建
原始触控桥之前直接返回。应用能运行、快捷键能使用并不表示全局触控桥已启动。

本次允许 `macOS 26 + 9460.1 + arm64`；原 9450.2 的 arm64/x86_64
支持继续保留。其他系统主版本、框架版本、缺失版本和未验证 CPU 均不启用私有解析。
设置界面在版本不匹配时明确提示使用快捷键或菜单栏。

## 已完成的接口检查

使用本机 LLDB 读取系统共享缓存中的已安装框架，未修改系统框架或触控偏好：

- `MTRegisterContactFrameCallbackWithRefcon` 保存 callback 与 refcon，返回成功布尔值。
- `MTAlg_IssueContactFrameCallbacks` 将设备、记录指针、数量、时间、帧编号和
  refcon 放入现有 Swift C 回调所对应的寄存器；记录缓冲区为 3072 字节。
- `MTGetPathFrame` 明确使用 96 字节步长，最多 32 条记录；生命周期记录从
  +8 字节开始复制到回调记录。状态检查对应回调 +0x14，电容检查对应 +0x30。
- `MTPathPrintCallback` 将 +0x20/+0x24 按归一化 X/Y 输出，+0x30 为总电容；
  与当前解码器一致。
- 隔离探针成功完成加载、设备创建、回调注册和启动，返回 `device-start=0`。

私有帧仍受数量上限、有限数值、坐标范围、状态、重复身份和电容检查保护；
无效帧继续隔离整段手势。回调关闭、在途排空和主线程取消顺序未改动。

## 验证范围

自动检查覆盖版本限制、原始字节解码、五指收拢/张开、逐根落指、短暂丢点、
二指分页隔离、重复来源仲裁和延迟任务取消。真实五指触点尚未在本次诊断中收到；
因此接口适配完成不等于已经通过实机五指触发验收。

实机复验时，在隔离数据目录启动构建产物，并设置
`LAUNCH_GESTURE_DIAGNOSTIC_PATH` 到本地日志路径。先检查 `raw active`，再做
五指收拢、张开以及普通二指横滑，核对 `pinch recognized` 和窗口显示/隐藏。
日志与原始采样放在忽略的 `.build/` 目录，不提交用户数据。

本次执行结果：核心 31/31、手势 59/59、快捷键 2/2、触点身份 1/1、菜单栏
几何 6/6；Release 构建、严格代码签名、Info.plist 和 DMG 校验通过。
隔离应用运行日志确认 `raw-bridge=created`。GUI 验收被当前 Mac 锁屏阻挡，
五指开关、系统浮层和实际交互需解锁后复验；没有以模拟输入冒充实机通过。
